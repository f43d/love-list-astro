# 2026-08-31 — OpenChamber installed alongside opencode-web

## What was done

### Architecture Q&A: stay static

Owner came back at night and asked whether moving to a VPS would make development easier (TypeScript, Tailwind, etc.). Answered with the trade-offs:

- Static + GitHub Pages: $0 forever, zero maintenance, zero attack surface, survives the owner being gone (the whole point of `docs/PERMANENCE.md`).
- VPS: real money (or Oracle Free risk), ongoing OS / SSL / patch burden, *worse* for this project's permanence goal.

**Verdict**: stay static. The site already uses TypeScript (`src/lib/*.ts`) and vanilla JS; Tailwind would fight the bespoke handwritten aesthetic. Astro islands give all the "modern" interactivity needed without a server. Decision logged here, not in `DECISIONS.md` (it's the same conclusion as 2026-08-28 "Stack: Astro 5 over Hugo" — just re-asked).

### OpenChamber install (system-level, LXC)

OpenChamber ([openchamber/openchamber](https://github.com/openchamber/openchamber)) is an extended workspace UI on top of the OpenCode CLI — adds Session Goals, Multi-run, Changes Walkthrough, mobile/PWA access, scheduled tasks. Wraps the same OpenCode agent already running. Installed alongside the existing `opencode-web` service on a different port for side-by-side comparison.

Install steps:

1. Downloaded the install script first (`scripts/install.sh`) and read it — clean (just runs `npm install -g @openchamber/web`). No piping curl to bash.
2. Ran the npm install directly (bypassed the script's Node 22+ check; Node 20 emits EBADENGINE warnings but the binary works). Installed **OpenChamber 1.22.0**.
3. Symlinked `/root/.opencode/bin/opencode` → `/usr/local/bin/opencode` so OpenChamber's bundled OpenCode lookup finds the existing backend binary (the systemd PATH didn't include `/root/.opencode/bin`).
4. Wrote `/etc/systemd/system/openchamber.service`:
   ```ini
   [Unit]
   Description=OpenChamber Web UI (alongside opencode-web on port 3000)
   After=network.target opencode-web.service

   [Service]
   Type=forking
   User=root
   PIDFile=/root/.config/openchamber/run/openchamber-3001.pid
   ExecStart=/usr/local/bin/openchamber serve --port 3001 --host 0.0.0.0 --ui-password ee3d9a0acd7d1292a65876001b21d5b64bc92bd7168d09c1
   Restart=on-failure
   RestartSec=5

   [Install]
   WantedBy=multi-user.target
   ```
   - `Type=forking` because OpenChamber `serve` daemonises itself (parent exits, child keeps running on port 3001).
   - Same `OPENCODE_SERVER_PASSWORD` value as `opencode-web.service` so the owner uses one password for both.
   - PIDFile path discovered by `find` after the first failed attempt (was guessing `/root/.openchamber/...` initially).
5. `systemctl daemon-reload && systemctl enable --now openchamber.service`.

### Quick reference

```bash
openchamber status                  # show running instance(s)
openchamber logs -p 3001            # tail logs
openchamber stop                    # stop the daemon
openchamber restart                 # restart the daemon

# systemd
systemctl status openchamber.service
systemctl restart openchamber.service
systemctl stop openchamber.service

# Retire the old setup when ready

```
