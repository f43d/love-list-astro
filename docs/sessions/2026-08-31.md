# 2026-08-31 — OpenChamber installed alongside opencode-web

## What was done

### Architecture Q&A: stay static

Owner came back at night and asked whether moving to a VPS would make development easier (TypeScript, Tailwind, etc.). Answered with the trade-offs:

- Static + GitHub Pages: $0 forever, zero maintenance, zero attack surface, survives the owner being gone (the whole point of `docs/PERMANENCE.md`).
- VPS: real money (or Oracle Free risk), ongoing OS / SSL / patch burden, *worse* for this project's permanence goal.

**Verdict**: stay static. The site already uses TypeScript (`src/lib/*.ts`) and vanilla JS; Tailwind would fight the bespoke handwritten aesthetic. Astro islands give all the "modern" interactivity needed without a server. Decision logged here, not in `DECISIONS.md` (it's the same conclusion as 2026-08-28 "Stack: Astro 5 over Hugo" — just re-asked).

### OpenChamber install (system-level, LXC)

OpenChamber ([openchamber/openchamber](https://github.com/openchamber/openchamber)) is an extended workspace UI on top of the OpenCode CLI — adds Session Goals, Multi-run, Changes Walkthrough, mobile/PWA access, scheduled tasks. Wraps the same OpenCode agent already running. Installed alongside the existing `opencode-web` service on a different port for side-by-side comparison.

Install steps:

1. Downloaded the install script first (`scripts/install.sh`) and read it — clean (just runs `npm install -g @openchamber/web`). No piping curl to bash.
2. Ran the npm install directly (bypassed the script's Node 22+ check; Node 20 emits EBADENGINE warnings but the binary works). Installed **OpenChamber 1.22.0**.
3. Symlinked `/root/.opencode/bin/opencode` → `/usr/local/bin/opencode` so OpenChamber's bundled OpenCode lookup finds the existing backend binary (the systemd PATH didn't include `/root/.opencode/bin`).
4. Wrote `/etc/systemd/system/openchamber.service`:
   ```ini
   [Unit]
   Description=OpenChamber Web UI (alongside opencode-web on port 3000)
   After=network.target opencode-web.service

   [Service]
   Type=forking
   User=root
   PIDFile=/root/.config/openchamber/run/openchamber-3001.pid
   ExecStart=/usr/local/bin/openchamber serve --port 3001 --host 0.0.0.0 --ui-password ee3d9a0acd7d1292a65876001b21d5b64bc92bd7168d09c1
   Restart=on-failure
   RestartSec=5

   [Install]
   WantedBy=multi-user.target
   ```
   - `Type=forking` because OpenChamber `serve` daemonises itself (parent exits, child keeps running on port 3001).
   - Same `OPENCODE_SERVER_PASSWORD` value as `opencode-web.service` so the owner uses one password for both.
   - PIDFile path discovered by `find` after the first failed attempt (was guessing `/root/.openchamber/...` initially).
5. `systemctl daemon-reload && systemctl enable --now openchamber.service`.

### iOS Firefox dark-mode fix attempts (5 commits, eventually abandoned)

iPhone Firefox was rendering the site with a black background and
auto-darkened text. The site looked fine on macOS Firefox and
Android Firefox. Spent the evening trying to fix it:

1. **`fix(theme): force light scheme + warm-cream body fallback for iOS Firefox`** (`f371537`)
   - `<meta name="color-scheme" content="only light">` (was `"light"`).
   - `body { background-color: #faf3e0 }` (warm paper fallback).
   - `background-attachment: scroll` on phones (instead of `fixed`).
   - **Result**: still dark on iPhone.

2. **`fix(theme): three-layer light-mode enforcement for iOS WebKit`** (`c972987`)
   - Added `color-scheme: only light` in CSS `:root` too (meta tag alone wasn't enough).
   - `html` AND `body` got `background-color: #faf3e0`.
   - Dropped `background-attachment: fixed` entirely (not just on mobile).
   - **Result**: still dark on iPhone.

3. **`fix(theme): move wallpaper to fixed pseudo-element for iOS + long pages`** (`d93de68`)
   - Moved `background-image` off body onto a `position: fixed` body::before pseudo-element. Pseudo-element rendered reliably on iOS WebKit where body bg did not.
   - **Result**: wallpaper finally painted — but only in the BOTTOM half of the viewport.

4. **`fix(theme): explicit width/height on wallpaper pseudo-element for iOS`** (`c80b86b`)
   - Replaced `inset: 0` with explicit `top: 0; left: 0; width: 100vw; height: 100vh`. Removed `z-index: -1` so the wallpaper painted on top of the cream fallback.
   - **Result**: wallpaper full-viewport — but the content of `/100-reasons-why/` disappeared (behind the wallpaper).

5. **`fix(theme): three-layer z-stack for wallpaper on iOS WebKit`** (`02bfb39`)
   - The proper fix: `html bg: cream` (always-visible fallback), `body bg: transparent` (don't compete with pseudo-element), `body::before: z-index: -1` (paint between html bg and body content).
   - **Result**: finally correct on macOS/Android — wallpaper full-viewport, content visible on top. **iPhone Firefox STILL renders with a black background despite all five layers of `!important`, `color-scheme: only light`, and the three-layer z-stack. See DECISIONS.md "Don't chase iOS Firefox dark-mode fix".**

6. **Verified**: installed Firefox on the owner's Android phone. Wallpaper + content render correctly. iOS Firefox is the only broken browser; the site is for ~5 family visitors.

### Desktop font bump

7. **`style(100-reasons-why): bump desktop body font ~20%`** (`734f8a0`)
   - Scaled `.content-text` font-size preferred and max by 1.2×: `clamp(1.15rem, 0.72rem + 1.32vw, 2.04rem)`. Mobile unchanged at the 1.15rem min.
   - Computed: 18.4 px mobile → 28.4 px @ 1280 px → 32.6 px large desktop.

### Header padding

8. **`style(header): add portrait-mode padding around the text layer`** (`5723243`)
   - Added `padding: 0.75rem 0 1rem` to `.site-header__text` in the portrait @media block. 12 px top, 16 px bottom — more breathing room around the title lines without changing the photo or text sizes.
