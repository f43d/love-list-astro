# 2026-08-29 (afternoon) — settings page, glyph fix, header redesign

## What was done

- **Hidden `/settings/` page** for owner photo management. New
  `src/lib/settingsClient.ts` (GitHub Contents API + canvas WebP
  processor). Page handles auth (PAT in sessionStorage), list / edit /
  upload / delete photos, link to bucket items. Commits go through
  the Contents API → existing GitHub Action deploys in ~30s. Owner-only
  — no public link anywhere.

- **Gallery lightbox refactor** — the caption was being pulled from the
  DOM via `document.querySelector('#photo-NN .gallery__caption')`.
  Switched to a JSON blob in `<script type="application/json"
  id="gallery-data">` rendered by Astro; lightbox JS reads it once at
  start. Captions cannot drift out of sync with photos.

- **DC-CST glyph coverage audit** — extracted all CJK chars used in the
  site and checked against `fontTools`. Found 10 missing: 淚 涙 牆 強
  啓 為 氹 沒 說 錄. Most concerning: the owner's own name 強. My
  earlier codepoint check had the wrong hex for 淚 (used 6D9A instead
  of 6DDA), which masked the gap. Fixed by:
  - Loading Noto Serif TC as a fallback (rejected by owner).
  - Using 泪 (Simplified Chinese, U+6CEA) instead of 淚 / 涙 —
    only "tears" glyph in DC-CST. Applied across header, the
    100-reasons-why link, and HISTORY.md for consistency.
  - Other missing chars (牆 強 啓 為) are still in the codebase but
    render via the STKaiti / BiauKai / serif fallback chain. Will
    need a follow-up pass.

- **Header border removal** — `background-color: transparent`,
  `border-radius: 0`, plus a `mask-image: linear-gradient(to bottom,
  black 0%, black 70%, transparent 100%)` to fade the bottom of the
  blur band. Header now reads as part of the page rather than a
  floating card.

- **Privacy / security discussion** — no code change. Conclusion:
  keep repo public (free Pages plan, no real secrets in source),
  Cloudflare proxy optional. Action items for owner: 2FA on GitHub +
  Cloudflare + domain registrar.

# Afternoon — responsive design + cleanup

## What was done

### Header on iPhone (lots of small rounds)

- **Portrait**: header was too small (47px photo) → made the photo a real
  hero element (~50vw, up to 260px, then reduced to 220px after feedback).
  Counter / title / subtitle font-sizes tuned; subtitle re-shown
  (it was display:none in an earlier commit). Layout 30% bigger on
  portrait, with 3 distinct lines.
- **Landscape**: header was too small (41px photo) → grew 30%, then 30%
  again. Photo now ~86px. Counter / title / subtitle font-sizes bumped.
  Padding and gap expanded too.
- Fixed a CSS source-order bug: the portrait `@media` rule was placed
  BEFORE the 1024px one, so on iPhone portrait the less-generous 1024px
  rule was winning. Reordered so the portrait rule is last.
- Added a `padding-top` rule to .page / .bucket-list / .gallery that
  scales with viewport height, so the new big header + its bottom
  blur-fade is always clear of the content.

### Wenwrite font on /100-reasons-why/

- Loaded a new font (wenwrite Proportional, owned by the user) just for
  the long-form prose on the vows page. Subsetted the full 15 MB TTF to
  just the 244 codepoints used in the body (82 KB woff2, 99.5% smaller).
- The 100-reasons-why link in the header now reads "是笑與泪的同行"
  (泪 = Simplified, since DC-CST is missing 淚/涙).
- Body-text font sizes bumped on iPhone + desktop (see commit af55f13
  commit message for full table).

### Code cleanup (final commit of the session)

Three new shared modules:
- `src/lib/types.ts` — `BucketItem` / `GalleryItem` / `Blessing` interfaces
  (were duplicated server-side and client-side).
- `src/lib/parseEnv.ts` — generic pipe-separated env parser with cached
  file reader; used by all three data files.
- `src/lib/utils.ts` — `pickRandomInt`, `formatBytes`, `escapeHtml`
  (previously inlined in components).

The three `parse*` files now use `parseLines()` from `parseEnv.ts` —
each is ~30 lines instead of ~50, and the env-file format lives in
one place.

`settingsClient.ts` was tidied: shared types come from `src/lib/types`,
utilities from `src/lib/utils`, and the PUT-text / PUT-binary code paths
are now a single `putFileAtPath` helper.

Components got comment blocks describing what each one does and why
(no behavior changes).

`npx astro check` → 0 errors, 0 warnings.
