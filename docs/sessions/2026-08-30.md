### DC-CST missing-character substitutions (final round)

After the audit, the 10 characters DC-CST doesn't have were:
啟 強 氹 沒 涙 淚 為 牆 說 錄.

We substituted the four that were rendered in a DC-CST context
(bucket list body + footer):

- 強 → 强 (Simplified, in Footer.astro) — the owner's name still reads
  correctly because the display name lives in HTML text, not the
  font's own data.
- 氹 → 哄 (in data/list.env item 28) — "講鬼故哄你訓覺" reads more
  naturally in a parent-to-child register than 氹 (HK slang "trick").
- 為 → 爲 (in data/list.env item 74)
- 錄 → 録 (in data/list.env item 89)

The remaining six (牆, 啟, 為, 沒, 淚, 涙) don't render in a DC-CST
context anywhere in the live site — they're either in the comment page
which uses `--font-form` (Noto Sans HK), or the 100-reasons-why page
which uses `--font-prose` (wenwrite), or in a non-visual meta tag.
So they were never actually broken on the live site.

The user proposed 說/録 as substitutes for 說/錄. 說 (U+8AAA) is
in Noto Sans HK but not in DC-CST; 録 (U+9332) IS in DC-CST. The user
also proposed 爲 (U+7232) as a Traditional alternative to 為, which
is in DC-CST and was used for item 74.

After this round, no DC-CST-missing char renders in a DC-CST context.

# Evening session — UI polish: header + bucket list focal effect

## What was done

Seven commits, all in `src/styles/global.css` and
`src/components/Header.astro`:

1. **`fix(header): make subtitle match title font-size in all viewports`** (`8a4fc07`)
   - `.site-header__subtitle` was smaller than `.site-header__title`
     in two of the three responsive blocks (default + landscape).
     Portrait was already equal — its comment at the time said
     "lines 2 and 3 are the same size". Brought all three into line.

2. **`fix(header): soften mask gradient to remove bottom-edge seam`** (`d3c70b7`)
   - Mask had a hard 70% cutoff; content scrolling past the bottom
     30% appeared fully clear (masked-out element), while content
     behind the top 70% was blurred. Replaced with a 4-stop
     gradient for a smoother transition.

3. **`style(bucket-list): bump focal zoom to 1.45× and use bright coral`** (`bc2222b`)
   - Owner asked for a more prominent focal state. Scale 1.3 → 1.45
     (mid-range of the 10–15% request); focal colour
     `--color-text-focal` (#b04e58) → `--color-text-hover` (#e57f84)
     so the accent matches the existing hover/links palette.

4. **`fix(header): separate backdrop from content so photo is no longer masked`** (`be09fec`)
   - The blur-backdrop and mask were on the entire `.site-header`,
     which clips its children too. So the bottom of the hero photo
     became see-through. Refactored to a backdrop/content split:
     new `.site-header__backdrop` absolutely positioned behind the
     content carries the backdrop-filter + mask; `.site-header__inner`
     is no longer clipped. Photo always reads as opaque; list text
     scrolling past is consistently BEHIND the photo.

5. **`fix(bucket-list): equalise checked/unchecked size and use deeper coral focal`** (`dac54c2`)
   - (a) Checked `.list-item__text` had no explicit font-size, so it
     inherited body 1rem (16 px) — much smaller than unchecked's
     16–26 px. Moved font-size + animation to the base
     `.list-item__num, .list-item__text` selector so both share.
     (b) Focal `--color-text-hover` (#e57f84) read as too close to
     teal default — switched to a dedicated `--color-text-focal:
     #c4364a` for more contrast.

6. **`style(header): feather the hero photo border with a 3-stop white halo`** (`6abd12a`)
   - The 2 px white border on `.site-header__photo` read as a hard
     "cut and paste" ring. Added a 3-stop `box-shadow`
     (4 / 10 / 18 px at 0.5 / 0.25 / 0.1 opacity) to feather the
     area just outside the border.

7. **`style(header): bump feather to ~20 px reach for a fuzzier edge`** (`a3421a7`)
   - First attempt too subtle. Bumped to 4-stop `box-shadow`
     spanning 6 / 14 / 22 / 30 px with stronger opacities
     (0.55 → 0.4 → 0.2 → 0.08). Reach ~20–25 px.
